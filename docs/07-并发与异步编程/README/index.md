# 并发与异步编程 Roadmap

| 类别 | 作用 | 前端类比 | 类比边界 |
| --- | --- | --- | --- |
| 线程与共享状态 | 解释同时执行的任务如何访问数据 | 多个异步请求修改同一状态 | Java 线程可能真正并行，执行与内存可见性不能套事件循环 |
| 同步与并发集合 | 保护操作及共同业务规则 | 防过期覆盖的部分思路 | 原子性、可见性与多个操作的一致性需要分别判断 |
| 线程池与异步结果 | 限制资源、编排任务、收集结果 | 并发请求队列与 Promise | 等待可能阻塞，超时和取消不代表工作已停止 |
| 上下文与诊断 | 避免身份串用，定位线程和队列问题 | 请求上下文与调试 | 线程会复用，故障需线程栈与资源指标证明 |

## 本阶段学习定位

**按需深入。** 在共享状态、异步任务、线程上下文或负载问题出现时学习对应节点；不作为第一次交付普通接口的整章前置。

## 目标与前置条件

让多个请求或任务同时执行时，结果正确、资源有界、失败能够收尾。

前置是 [01](/01-Java语言与JVM基础/README/)的对象、集合、异常、Lambda 与运行模型。基础线程概念随业务调用理解；服务端共享对象结合 [03](/03-HTTP与Spring服务开发/README/)，数据库竞争结合 [06](/06-事务与数据一致性/README/)。

学习主线使用当前学习 JDK，平台线程、线程池和虚拟线程都要学习；公司 Java 8 业务案例不直接使用虚拟线程等新 API。版本边界见 [学习版本与中文资料](/参考资料/学习版本与中文资料/)。

## 学习方式与顺序

遇到多个请求、后台任务或等待下游的问题时，按“业务问题 → 概念与保证 → 教程 → 项目代码”定位当前需要理解的部分。基础线程概念可随 Spring 读码进入，具体同步与调度机制按需求深入。

## 一 逐个知识点学习

### 1. 线程怎样开始与结束

**业务问题：** 一个请求等待数据库时，其他请求由谁继续处理？后台任务何时才算结束？

**概念与保证：** 线程是一条执行路径；并发、并行、同步、异步与阻塞描述不同关系。启动任务、等待结果和任务真正结束需要分开解释。

**项目中看什么：** 从请求入口、任务提交与等待位置确认执行者，不把普通方法调用、Promise 或远程请求直接当作新线程。

**教程与讲解：** [廖雪峰多线程](https://liaoxuefeng.com/books/java/threading/index.html)中的线程基础与创建线程；[本地讲解](/07-并发与异步编程/典型案例/#一-线程让另一条执行路径开始工作)。

### 2. 识别共享对象与竞争

**业务问题：** 两个请求会不会修改同一个业务对象，出现丢失更新或身份串用？

**概念与保证：** 对象是否共享取决于持有与访问关系。读、判断、修改若分成多个动作，就可能交错；局部变量引用的对象也可能被共享。

**项目中看什么：** 检查单例 Bean 的可变字段、static 集合、缓存与逃逸引用，先明确状态所有权和不能违反的规则，再决定同步方式。

**教程与讲解：** [廖雪峰多线程](https://liaoxuefeng.com/books/java/threading/index.html)中的同步；[共享状态](/07-并发与异步编程/典型案例/#二-共享状态中的读改写可能交错)。

### 3. 同步保证成立的条件

**业务问题：** 改用锁或原子类后，哪条业务规则得到了保护？所有访问路径都遵守吗？

**概念与保证：** 互斥、原子性、可见性与有序性不是同一项保证。volatile 不把复合修改变成原子操作；多个原子变量也不自动保护共同规则。

**项目中看什么：** 找到锁对象、临界区和释放位置；跨多个字段的状态关系需一起保护，多个实例或数据库竞争另看06与09。

**教程与讲解：** [廖雪峰多线程](https://liaoxuefeng.com/books/java/threading/index.html)；[同步保证](/07-并发与异步编程/典型案例/#三-锁volatile-与原子类分别保证什么)；[线程与锁规范](https://docs.oracle.com/javase/specs/jls/se21/html/jls-17.html)。

### 4. 并发集合与协作工具

**业务问题：** 线程安全的 Map，能否保证“名额未满才加入”这条规则？

**概念与保证：** 并发集合只保证具体操作；检查再修改、多个键或跨系统操作仍可能分开执行。队列、信号量与等待工具各自控制不同条件。

**项目中看什么：** 阅读 putIfAbsent、compute、BlockingQueue、Semaphore 的实际使用，说明同一操作保证到哪一步，等待谁释放、资源上限在哪里。

**教程与讲解：** [并发包](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/package-summary.html)；[集合与协作](/07-并发与异步编程/典型案例/#四-并发集合保护具体操作不包办业务规则)。

### 5. 给线程池设置资源边界

**业务问题：** 下游变慢后，任务在哪里排队，系统怎样避免把自己拖垮？

**概念与保证：** 处理线程、排队任务、数据库连接与下游配额共同限制吞吐。无界队列会扩大等待与内存占用；拒绝与关闭属于业务结果。

**项目中看什么：** 从执行器配置追到提交方：核心/最大线程、队列、拒绝策略、连接池及 shutdown 收尾；容量用实际负载与资源数据解释。

**教程与讲解：** [ThreadPoolExecutor](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/ThreadPoolExecutor.html)；[资源边界](/07-并发与异步编程/典型案例/#五-线程池要同时限制运行和排队数量)。

### 6. Future、等待超时与取消

**业务问题：** 接口已经超时或用户取消，后台是否还在写数据、调用下游？

**概念与保证：** Future 区分提交、执行、完成与结果消费。等待超时只结束等待；中断是协作信号，取消状态不自动撤销已经发生的副作用。

**项目中看什么：** 确认每次等待的截止时间、任务响应中断的位置、资源清理与外部副作用；不能仅看 Future 状态判定业务停止。

**教程与讲解：** [Future API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/Future.html)；[等待与取消](/07-并发与异步编程/典型案例/#六-future-区分提交完成与取结果)。

### 7. 编排多个异步结果

**业务问题：** 聚合多个来源时，哪些可以并行，哪个失败允许部分返回？

**概念与保证：** 结果依赖决定串行与并行；异常合并、执行器与总时限都是契约。CompletableFuture.cancel(true) 不因此中断底层计算。

**项目中看什么：** 追踪任务图、显式执行器、handle/exceptionally 与结果合并；核对公共池是否被阻塞、池内是否相互等待。

**教程与讲解：** [CompletableFuture API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/CompletableFuture.html)；[结果编排](/07-并发与异步编程/典型案例/#七-completablefuture-组合多个结果)。

### 8. 上下文传递与清理

**业务问题：** 异步任务中的用户、租户和追踪信息来自哪里，会留给下一个任务吗？

**概念与保证：** ThreadLocal 与线程关联，线程池会复用线程；跨线程可能丢失上下文，同线程复用可能残留。异步不自动延续 Spring 本地事务。

**项目中看什么：** 身份从可信认证上下文取得，必要字段显式传递；检查 set、恢复/清理和 finally，确认新任务的持久化边界。

**教程与讲解：** [上下文讲解](/07-并发与异步编程/典型案例/#八-上下文跟着任务传递复用线程前后要清理)；结合[12 权限](/12-安全与权限/README/)与[06 事务](/06-事务与数据一致性/README/)。

### 9. 虚拟线程

**业务问题：** 等待型任务很多时，更换执行模型能缓解什么，不能增加什么？

**概念与保证：** 虚拟线程减少大量等待任务占用执行线程的成本，不增加 CPU、数据库连接或远端配额，也不自动解决共享状态竞争。

**项目中看什么：** 看执行器创建、任务结束与下游并发限制；按实际 JDK 核对阻塞行为，公司 Java 8 使用兼容机制。

**教程与讲解：** [廖雪峰虚拟线程](https://liaoxuefeng.com/books/java/threading/virtual-thread/index.html)、[Dev.java](https://dev.java/learn/new-features/virtual-threads/)；[本地讲解](/07-并发与异步编程/典型案例/#九-虚拟线程)。

## 二 综合案例 结果正确与资源有界

[聚合接口案例](/07-并发与异步编程/典型案例/#十-综合案例-让并发结果正确且资源有界)把调用依赖、总体时限、允许缺失的结果、共享状态和资源预算放回一条请求。阅读现有服务时，先说明每份数据由谁产生、哪些步骤可能同时执行，再判断所用并发工具是否满足规则。

## 三 业务验证

| 要核对什么 | 业务证据 |
| --- | --- |
| 并发下结果正确 | 共享对象、业务不变量、关键交错及最终数据；偶尔正确不足以证明安全 |
| 过载受控 | 真实流量条件下的活动线程、队列、拒绝、连接与下游占用 |
| 超时与取消收尾 | 返回结果、任务终态、资源释放，以及仍在发生的外部副作用 |
| 请求隔离 | 身份来源、跨线程传递及复用线程后的上下文清理 |

仅在当前需求涉及对应风险时增加验证，记录运行范围；线程池参数或单次输出不能替代业务保证。
