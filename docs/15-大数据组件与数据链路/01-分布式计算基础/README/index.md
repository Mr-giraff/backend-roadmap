# 分布式计算基础 Roadmap

| 类别 | 作用 | 前端类比 | 类比边界 |
| --- | --- | --- | --- |
| 数据分区与并行 | 把数据拆成可分配的工作 | 分段处理数组 | 分区数量、执行线程和机器数量是不同概念 |
| 数据交换 | 让相同计算所需的数据汇合 | 按 key 分组 | 跨进程交换会使用网络、磁盘和内存 |
| 调度与恢复 | 分配工作，处理执行者退出 | 任务队列与重试 | 还需确认输入可重读、输出是否重复 |

这是 Hive、Spark、Flink 的共同基础。目标是能从一份输入解释“如何拆、如何合、谁执行、慢在哪里、失败怎么办”。先具备 [SQL 基础](/05-数据库设计与SQL/README/)，不要求先完成完整分布式系统课程。

## 学习顺序与业务问题

先明确业务问题，再理解计算与运行保证，读对应资料，最后在 SQL、代码、配置和计划中定位。

| 业务问题 | 概念与保证 | 代码与讲解入口 |
| --- | --- | --- |
| 输入有边界还是持续到达，什么时候可以认为结果完成 | 有界输入、无界输入、数据粒度和统计范围 | [输入与结果](/15-大数据组件与数据链路/01-分布式计算基础/典型案例/#一-先确定输入有没有结束) |
| 拆成多少份工作，为什么分区数不等于机器数 | 数据分区、并行度、线程与物理资源 | [分段与并行](/15-大数据组件与数据链路/01-分布式计算基础/典型案例/#二-分区是工作分段并行度是同时做几段) |
| 相同 key 的数据为什么要汇合，交换代价在哪里 | 局部计算、Shuffle、网络和落盘、最终合并 | [数据交换](/15-大数据组件与数据链路/01-分布式计算基础/典型案例/#三-shuffle-让相同分组的数据汇合) |
| 少数任务慢，是倾斜、资源等待还是外部依赖 | 输入分布、任务工作量、交换量和等待证据 | [慢任务](/15-大数据组件与数据链路/01-分布式计算基础/典型案例/#四-一部分任务特别慢先看数据和等待) |
| 作业没开始，是平台未提交还是引擎在等资源 | 平台、资源管理与引擎内部调度的职责边界 | [三类调度](/15-大数据组件与数据链路/01-分布式计算基础/典型案例/#五-谁安排时间谁给资源谁分配任务) |
| 执行者退出后能否重算，外部结果会不会重复 | 输入重读、内部状态、输出副作用与重试 | [恢复边界](/15-大数据组件与数据链路/01-分布式计算基础/典型案例/#六-失败后重算需要同时检查输入和输出) |

计算与交换查 [Spark RDD 指南](https://spark.apache.org/docs/3.5.7/rdd-programming-guide.html)，资源与执行角色查 [Spark 集群架构](https://spark.apache.org/docs/3.5.7/cluster-overview.html)和 [Flink 中文架构](https://nightlies.apache.org/flink/flink-docs-release-1.17/zh/docs/concepts/flink-architecture/)。按当前任务选择对应概念阅读。

## 综合案例与业务验证

[地区汇总案例](/15-大数据组件与数据链路/01-分布式计算基础/典型案例/#七-综合案例-把地区汇总拆给两个执行者)说明局部计算与交换怎样共同得到结果。回到任务代码或 SQL 时，标出输入、分区内操作、跨分区操作和输出位置；实际是否交换、使用多少任务，以计划与运行记录为准。

当前需求涉及分布式计算或性能改动时，核对结果口径、输入分布、执行角色、数据交换、失败重试和外部写入。手算模型帮助解释算法，真实资源分配、多机交换和恢复需要对应运行证据。共识算法、分布式事务、自建调度器与源码阅读按问题进入 [09](/09-分布式系统与服务协作/README/)、[10](/10-系统设计/README/)。
