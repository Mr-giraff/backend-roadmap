# Kafka 消息队列

### 4. Kafka 部署角色与消息流向

**业务问题：** 哪一方保存事件，哪一方做业务，同一个对象的事件分给谁处理？

**概念与保证：** broker、controller、topic、partition、producer、consumer 各有职责。分区有序不等于全局有序，单副本不能提供多副本容错。

**项目中看什么：** 从 topic、key、序列化和生产配置定位事件路径，区分 broker 入口与消费业务；本资料的 Kafka 4.2 使用 KRaft。

**教程与讲解：** [Kafka 概念](https://kafka.apache.org/42/getting-started/introduction/)、[生产配置](https://kafka.apache.org/42/configuration/producer-configs/)；[事件与分区](/01-Java学习路线/08-缓存、消息与服务协作/Kafka消息队列/典型案例/#五-消息把工作交给独立消费者)、[发送契约](/01-Java学习路线/08-缓存、消息与服务协作/Kafka消息队列/典型案例/#六-一条消息进入-kafka-需要哪些约定)。

### 5. 消费组与消费位置

**业务问题：** 记录读到了，是否意味着业务完成，重启后从哪里继续？

**概念与保证：** 不同消费组进度独立；同组按分区分工。当前位置、已提交位置和外部数据库结果分别记录，不自动共同提交。

**项目中看什么：** 检查自动/手动提交、按分区连续完成的位置及重平衡处理；不能越过失败记录提交，也不能把读到消息当作业务完成。

**教程与讲解：** [Kafka 消费者](https://kafka.apache.org/42/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html)、[消费配置](https://kafka.apache.org/42/configuration/consumer-configs/)；[位置与提交](/01-Java学习路线/08-缓存、消息与服务协作/Kafka消息队列/典型案例/#七-写入结果与消费位置分别说明什么)。

### 6. 重复、重试、顺序与积压

**业务问题：** 同一事件再次到达会不会多通知一次，消费变慢应先查哪里？

**概念与保证：** 事件标识和持久化约束保护业务去重；位置提交、生产者幂等不能替代外部业务幂等。LAG 也不等于精确未完成业务条数。

**项目中看什么：** 追去重记录与业务修改的事务，确认失败后的重试/暂停/隔离和恢复；结合分区、处理速率、数据库耗时定位积压。

**教程与讲解：** [数据库幂等](/01-Java学习路线/08-缓存、消息与服务协作/Kafka消息队列/典型案例/#八-用数据库保证同一事件只产生一条记录)、[重试与积压](/01-Java学习路线/08-缓存、消息与服务协作/Kafka消息队列/典型案例/#九-重试顺序与积压)、[消费组运维](https://kafka.apache.org/42/operations/basic-kafka-operations/)。
