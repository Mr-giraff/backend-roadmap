# 测试与质量保障 Roadmap

| 类别 | 作用 | 前端类比 | 类比边界 |
| --- | --- | --- | --- |
| 断言与单元测试 | 验证一段明确行为 | 纯函数或组件逻辑测试 | 不证明未经过的网络与数据库 |
| 测试替身 | 控制依赖返回和故障 | 替换请求函数 | 不要把被测规则自身替换掉 |
| 集成与契约 | 验证组合和调用约定 | 接口联调与回归 | 真实 SQL、事务和协议需对应环境 |
| 故障与持续验证 | 证明失败恢复与兼容 | 复现缺陷和 CI | 不能用覆盖率或偶发通过代替正确性 |

## 本阶段学习定位

**贯穿需求实战。** 从基本断言、单元测试、接口契约和失败路径开始；真实数据库、性能与复杂故障测试随场景增加。

## 目标与前置条件

目标是为行为正确性给出可重复的证据，并解释每项证据的范围。只需 [语言与开发环境](/01-Java学习路线/01-语言与开发环境/README/)、[工程构建与协作](/01-Java学习路线/03-工程构建与协作/README/)基础即可开始断言和单元测试；MVC、数据库、并发与分布式测试在对应路线后继续。测试贯穿学习，不需要等系统设计学完。

通用学习采用当前学习 JDK；JUnit 与 MVC 的具体组合见案例。Java 8 业务工程沿用原有兼容依赖，版本策略见[学习版本与中文资料](/参考资料/学习版本与中文资料/)。

## 学习方式与顺序

从当前需求需要证明的业务行为出发，再选择测试范围、框架和依赖。按“业务问题 → 预期与边界 → 教程 → 项目测试”阅读；测试是交付证据，框架 API 随代码按需查阅。

## 一 逐个知识点学习

### 1. 预期与断言

**业务问题：** 当前改动应该产生什么结果，拒绝什么输入，失败后留下什么状态？

**概念与保证：** 断言把业务预期和实际结果关联。日志、HTTP 200、接口能调用，都不能独立证明规则成立。

**项目中看什么：** 让断言对应需求条款和缺陷复现输入，核对返回值、错误及必要状态变化，避免只验证实现细节。

**教程与讲解：** [廖雪峰单元测试](https://liaoxuefeng.com/books/java/unit-test/index.html)；[行为与断言](/01-Java学习路线/06-测试与安全/测试与质量保障/典型案例/#一-先定义行为再写断言)。

### 2. JUnit 与重复执行

**业务问题：** 回归测试能否独立、稳定地重复，并被构建实际执行？

**概念与保证：** 测试发现、隔离数据和失败报告决定证据是否可用；顺序依赖、共享数据和错误异常预期会制造假通过。

**项目中看什么：** 查看测试命名、Test、assertEquals/assertThrows、构建报告与隔离设置；版本按项目依赖选择，不把无测试结果当成功。

**教程与讲解：** [廖雪峰单元测试](https://liaoxuefeng.com/books/java/unit-test/index.html)、[JUnit 构建支持](https://docs.junit.org/6.1.3/running-tests/build-support.html)；[本地说明](/01-Java学习路线/06-测试与安全/测试与质量保障/典型案例/#二-junit-把检查组织成可重复执行的测试)。

### 3. 范围与替身

**业务问题：** 这个测试到底经过了哪些边界，Mock 掉的部分还有什么没有被证明？

**概念与保证：** 单元、MVC、数据库和远程协议证明不同事情。替身控制依赖输入，但被替换系统的真实行为仍需别的证据。

**项目中看什么：** 从被测入口画到实际依赖，检查是否把业务规则自身替换掉，断言值与必要交互是否对应需求。

**教程与讲解：** [范围](/01-Java学习路线/06-测试与安全/测试与质量保障/典型案例/#三-一个测试只证明它实际经过的边界)、[替身](/01-Java学习路线/06-测试与安全/测试与质量保障/典型案例/#四-替身控制依赖让规则测试更确定)、[Mockito](https://site.mockito.org/)。

### 4. 集成与契约

**业务问题：** 参数绑定、SQL、事务与接口兼容，是否在真实边界上成立？

**概念与保证：** 普通方法调用不覆盖 MVC 转换，Mock 不证明数据库约束，测试外层回滚还可能掩盖服务事务缺失。契约也包括类型、空值与错误语义。

**项目中看什么：** 保留真实请求响应和旧调用样本；按需求经过 MVC、安全链、实际测试库或协议边界，检查提交后数据及提供/消费双方。

**教程与讲解：** [Spring MockMvc](https://docs.spring.io/spring-framework/reference/6.2/testing/mockmvc.html)、[Boot 测试支持](https://docs.spring.io/spring-boot/3.5/reference/testing/index.html)；[集成](/01-Java学习路线/06-测试与安全/测试与质量保障/典型案例/#五-集成测试检查真实转换和提交)、[契约](/01-Java学习路线/06-测试与安全/测试与质量保障/典型案例/#六-契约测试验证调用双方的约定)。

### 5. 并发与故障

**业务问题：** 在超时、重投或并发修改下，最终业务结果还成立吗？

**概念与保证：** 可控故障点与发生顺序能定位原因；随意 sleep、偶发通过和覆盖率不能代替正确性。验证需要看最终状态与外部副作用。

**项目中看什么：** 按风险选择提交前后、响应丢失、重复消费及恢复边界；把同步条件、预期、实际数据和日志关联到同一操作。

**教程与讲解：** [并发与故障](/01-Java学习路线/06-测试与安全/测试与质量保障/典型案例/#七-故障与并发测试先控制发生顺序)；涉及实现机制时结合[数据变更与事务](/01-Java学习路线/04-数据库与持久化/数据变更与事务/README/)、[并发与JVM](/01-Java学习路线/07-并发与JVM/README/)、[服务间调用](/01-Java学习路线/08-缓存、消息与服务协作/服务间调用/README/)。

## 二 综合案例

[名称可用性检查](/01-Java学习路线/06-测试与安全/测试与质量保障/典型案例/#八-综合案例-名称可用性检查)把名称规范化、可用性判断和查询依赖分开。RuleCheck 与 JUnit 示例只证明选定规则；真实租户查询、并发唯一性与保存事务需要相应的集成证据。

## 三 业务验证

| 要核对什么 | 业务证据 |
| --- | --- |
| 规则与缺陷 | 对应需求的输入、预期与断言，真实缺陷修复前后的可复现结果 |
| 数据与事务 | 真实测试库中的约束、提交后数据、失败后的状态与资源清理 |
| 接口兼容 | 提供与消费双方的请求响应约定，旧调用和错误契约的回归结果 |
| 风险边界 | 当前需求涉及的权限、并发、超时、重试或恢复证据，注明未经过的系统 |

测试范围随改动风险确定。证据需要可重复和可定位，不为机械改动增加只复述实现的测试，也不能因 AI 生成了代码就省略业务结果检查。

## 参考资料

- **中文主读**：[廖雪峰单元测试](https://liaoxuefeng.com/books/java/unit-test/index.html)：断言、Fixture、异常与参数化测试，先理解验证行为的方法。
- **现代 Java 补充**：[Dev.java](https://dev.java/learn/)：类、接口、异常与 Lambda 背景；JUnit 的具体版本及构建要求查官方资料。
- **测试框架核对**：[JUnit 6.1.3](https://docs.junit.org/6.1.3/overview.html)与 [Maven 构建支持](https://docs.junit.org/6.1.3/running-tests/build-support.html)：本章纯 JUnit 工程固定 JUnit 6.1.3、Surefire 3.5.5、当前学习 JDK。
- **集成测试核对**：[Spring 6.2 MockMvc](https://docs.spring.io/spring-framework/reference/6.2/testing/mockmvc.html)与 [Boot 3.5 测试支持](https://docs.spring.io/spring-boot/3.5/reference/testing/index.html)：MVC 工程的测试依赖由 Boot 3.5.16 管理，不手动叠加前面纯 JUnit 工程的版本。
- **按需补充**：[Mockito 官方入口](https://site.mockito.org/)与 [Pact 文档](https://docs.pact.io/)；当前学习 JDK 的实际客户端/工具版本需核对兼容性。
- **Java 8 兼容核查**：[JUnit 5.10.2 文档](https://docs.junit.org/5.10.2/user-guide/)用于对应旧工程，JUnit 6 不能在 Java 8 上运行。
