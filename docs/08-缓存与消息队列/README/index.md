# 缓存与消息队列 Roadmap

| 类别 | 作用 | 前端类比 | 类比边界 |
| --- | --- | --- | --- |
| Redis 缓存 | 复用可重建的查询结果 | 请求结果缓存 | 多实例共享，需要过期、隔离与故障处理 |
| Kafka 消息 | 保存事件，让不同服务按进度读取 | 事件通知与异步任务 | 消息留在分区中，消费位置与业务完成分开记录 |
| 使用与排查 | 接入组件、看配置和运行结果 | 接口联调与网络排查 | 需检查服务连接、分区、消费组和数据库结果 |

## 定位与前置条件

本路线属于**使用层**：先会接入 Redis、Kafka，解释它们的作用、部署角色和常见失败，再随真实需求深入。学到能验证缓存命中、发布消费、重复处理和积压即可进入项目；复杂缓存设计与跨系统一致性按需查阅。

前置为 [03 接口](/03-HTTP与Spring服务开发/README/)与 [05 数据库](/05-数据库设计与SQL/README/)的基本查询。通知写入用到 [06 本地事务](/06-事务与数据一致性/README/)；多线程消费者留到 [07](/07-并发与异步编程/README/)。

消息主线使用 **Kafka**。Redis 基础仍以廖雪峰中文教程为主；Kafka 的分区、消费组和消费位置按官方资料核对。Java 学习环境遵循统一基线；本地 Kafka 示例选 4.2，JDK 支持范围按官方文档与统一学习基线核对。公司 Java 8 工程沿用兼容的客户端与框架版本，不能直接引入本学习环境的 Kafka 客户端。

## 学习方式与顺序

从一次查询或一条业务事件进入，按“业务问题 → 组件保证 → 官方资料 → 项目代码与配置”阅读。Redis、Kafka 先达到能接入和解释失败的使用层；复杂一致性在实际需求出现时进入09。

## 一 逐个知识点学习

### 1. 权威数据与缓存范围

**业务问题：** 展示结果从哪里来，缓存丢失或过期后靠什么恢复？

**概念与保证：** 数据库中的权威记录与缓存副本有不同职责。命中只表示副本存在，不证明最新或仍有权访问。

**项目中看什么：** 确认键的租户/项目范围、值的来源、允许陈旧时间，以及哪些决策必须读取权威数据。

**教程与讲解：** [廖雪峰 Redis](https://liaoxuefeng.com/books/java/springboot/integration/redis/index.html)；[缓存职责](/08-缓存与消息队列/典型案例/#一-缓存保存可重建的结果)。

### 2. Redis 常用操作

**业务问题：** 缓存怎样写入、过期和删除，哪些运行条件会让它提前消失？

**概念与保证：** SET/GET/EX/TTL/DEL 表达键值生命周期；TTL 与内存淘汰不同，复制与故障切换也不保证副本永不丢失。

**项目中看什么：** 沿客户端和生效配置确认访问入口、键结构、过期策略与部署角色；按访问方式理解字符串、哈希和集合。

**教程与讲解：** [Redis 字符串](https://redis.io/docs/latest/develop/data-types/strings/)、[过期](https://redis.io/docs/latest/commands/expire/)、[淘汰](https://redis.io/docs/latest/develop/reference/eviction/)；[键值生命周期](/08-缓存与消息队列/典型案例/#二-用-redis-保存值并设置过期时间)。

### 3. 旁路缓存与失败

**业务问题：** 更新成功后为什么还可能读到旧值，Redis 不可用时数据库能否承受回源？

**概念与保证：** 未命中查库并回填、写库后失效仍有并发交错。缓存正确性要结合允许陈旧窗口、失效恢复和回源容量定义。

**项目中看什么：** 追读路径、更新提交点、删除或回填逻辑，检查热点、空值缓存和降级是否仍满足业务结果。

**教程与讲解：** [读写交错](/08-缓存与消息队列/典型案例/#三-未命中时查数据库更新后使副本失效)、[回源限制](/08-缓存与消息队列/典型案例/#四-缓存失败时控制回源量)；复杂规则结合[06](/06-事务与数据一致性/README/)和[09](/09-分布式系统与服务协作/README/)。

### 4. Kafka 部署角色与消息流向

**业务问题：** 哪一方保存事件，哪一方做业务，同一个对象的事件分给谁处理？

**概念与保证：** broker、controller、topic、partition、producer、consumer 各有职责。分区有序不等于全局有序，单副本不能提供多副本容错。

**项目中看什么：** 从 topic、key、序列化和生产配置定位事件路径，区分 broker 入口与消费业务；本资料的 Kafka 4.2 使用 KRaft。

**教程与讲解：** [Kafka 概念](https://kafka.apache.org/42/getting-started/introduction/)、[生产配置](https://kafka.apache.org/42/configuration/producer-configs/)；[事件与分区](/08-缓存与消息队列/典型案例/#五-消息把工作交给独立消费者)、[发送契约](/08-缓存与消息队列/典型案例/#六-一条消息进入-kafka-需要哪些约定)。

### 5. 消费组与消费位置

**业务问题：** 记录读到了，是否意味着业务完成，重启后从哪里继续？

**概念与保证：** 不同消费组进度独立；同组按分区分工。当前位置、已提交位置和外部数据库结果分别记录，不自动共同提交。

**项目中看什么：** 检查自动/手动提交、按分区连续完成的位置及重平衡处理；不能越过失败记录提交，也不能把读到消息当作业务完成。

**教程与讲解：** [Kafka 消费者](https://kafka.apache.org/42/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html)、[消费配置](https://kafka.apache.org/42/configuration/consumer-configs/)；[位置与提交](/08-缓存与消息队列/典型案例/#七-写入结果与消费位置分别说明什么)。

### 6. 重复、重试、顺序与积压

**业务问题：** 同一事件再次到达会不会多通知一次，消费变慢应先查哪里？

**概念与保证：** 事件标识和持久化约束保护业务去重；位置提交、生产者幂等不能替代外部业务幂等。LAG 也不等于精确未完成业务条数。

**项目中看什么：** 追去重记录与业务修改的事务，确认失败后的重试/暂停/隔离和恢复；结合分区、处理速率、数据库耗时定位积压。

**教程与讲解：** [数据库幂等](/08-缓存与消息队列/典型案例/#八-用数据库保证同一事件只产生一条记录)、[重试与积压](/08-缓存与消息队列/典型案例/#九-重试顺序与积压)、[消费组运维](https://kafka.apache.org/42/operations/basic-kafka-operations/)。

## 三 业务验证

| 要核对什么 | 业务证据 |
| --- | --- |
| 缓存范围与时效 | 同编号不同租户不会串数据，展示陈旧与失效恢复符合约定 |
| 故障回源 | Redis 不可用时数据库压力与用户降级结果有明确上限 |
| 消费结果与恢复 | 事件标识、分区位置、数据库结果及重复事件的处理记录 |
| 处理能力 | 各分区积压、处理速率、失败与恢复用时，不能只看消费进程存活 |

验证围绕当前业务的风险展开；组件 CLI 能连通只证明连接和选定操作，不证明完整业务链路。

## 四 按需深入

| 深入主题 | 触发场景 | 查阅方向 |
| --- | --- | --- |
| Redis 性能与高可用 | 热键、大键、连接或切换问题 | 慢命令、内存淘汰、复制和故障恢复 |
| 缓存一致性 | 展示陈旧超标或失效失败 | [06 事务](/06-事务与数据一致性/README/)、[09 一致性](/09-分布式系统与服务协作/README/) |
| Kafka Java / Spring 接入 | 项目需要消费者或发送方改动 | 客户端兼容、序列化、手动提交、重平衡与处理时限 |
| 消息双写与恢复 | 数据库成功但事件未发布 | [09 Outbox 与恢复](/09-分布式系统与服务协作/典型案例/) |
| 复杂消息处理 | 需延迟重试、隔离和受控重放 | 明确 topic、位置、去重和恢复责任，再选择框架实现 |

RabbitMQ 仅在实际项目需要时选读，其队列与确认机制另按产品文档学习。
